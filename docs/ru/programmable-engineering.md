# Engineering Kits и анализ производительности из C#

`EngineeringProject.OpenAsync` находит SDK-проект и возвращает его дескриптор, каталог Kit, активный Kit и профили. Для точного выбора задайте `ProjectDirectory` в `ProjectLocation`. `InspectAsync` показывает диагностику существующего restore, варианты конфигурации и идентификаторы lock-файлов.

Kit выбирает компилятор, платформу и генератор. Профиль, матрица и overrides определяют конфигурацию. Подключение Client определяет Host и workspace. Сформируйте `ConfigurationSelection` обычным LINQ, создайте запрос через `project.Operation` и спланируйте его через `DeveloperLifecycle.PlanOperationAsync`. Эта точка входа сохраняет возможности configure, build, test, run, benchmark, profile и package. Benchmark `KitMatrix` для одного Host использует отдельные build tree и последовательные замеры. Для различных профилей, Host или типов операций готовьте отдельные reviewed plans. Если нужны сопоставимые измерения, запускайте такие операции последовательно.

## Подтверждение и запуск

SDK, Kit, конфигурация, установка инструментов и vcpkg сохраняют отдельные шаги подтверждения. `MaterializeAsync` возвращает Scripting-манифест с точными байтами reviewed plan для локальной композиции и экспорта. `ReviewedEngineeringWorkflow.PrepareAsync` проверяет исходный digest, повторно проверяет evidence закреплённого выбора и доставляет на Host точные байты манифеста. Смена активного Kit после review сохраняет выбор из reviewed plan. Изменившийся манифест требует нового review. `PreflightAsync` проверяет состояние workspace и инструменты на Host. Для запуска сохраните request ID и явно вызовите `StartAsync` с результатом `CreateStartOptions`. При потере ответа переподключитесь к тому же workspace и найдите этот ID через `Operations.FindAsync`.

Для SSH заранее разместите проект, его входы и утверждённые lock-файлы в workspace, а затем укажите относительный каталог проекта как base манифеста. Инструменты, environment lock и dependency receipts должны соответствовать Host. Для привязанных к локальному пути vcpkg receipts действуют те же ограничения. Переносимые staged receipts поддерживает существующий путь экспериментов. [Engineering Kits](engineering-kits.md) · [Доставка манифеста](scripting.md)

## History

Укажите политику индексации в запросе preflight. `WaitForHistoryAsync` ждёт, пока History сообщит **Disabled**, **Indexed** или **Failed**. Ожидание финализации, очередь и сама индексация наблюдаются отдельно от результата сборки. Настройте предел ожидания через токен. После переподключения используйте тот же operation ID. `RetryIndexAsync` повторно импортирует проверенные результаты без запуска benchmark.

`GetOperationRunsAsync` возвращает точное соответствие операции и индексированных run ID из подтверждения импорта. Host сверяет сохранённый финальный отчёт и идентификаторы в исходной базе. Контракт поддерживает несколько run ID. Текущий индексатор CMake создаёт один запуск на операцию. Для ранее индексированных операций без такого соответствия используйте уже известные ID History.

`GetMeasurementsAsync` получает измерения по ID операции с фильтрами метрики, варианта, сценария и fingerprint окружения. Лимит составляет 50 000 строк, при превышении запрос завершится ошибкой. `EnumerateRunPagesAsync` требует число страниц и размер страницы от 1 до 200. Для продолжения сохраните непрозрачный `NextCursor`. Снимок базы между запросами не фиксируется.

## Сравнение и CI

`Summarize` группирует строки по run ID, метрике, единицам, варианту, сценарию, методу, workload и окружению. Результат хранит исходные измерения. Можно использовать обычный LINQ. Summary содержит среднее, медиану, минимум, максимум и стандартное отклонение по совокупности. Пустая последовательность не даёт summary, один замер даёт нулевое отклонение, нефинитные значения отклоняются.

Передайте известные run ID в `CompareAsync`. `HistoryComparisonSelection` выбирает метрику, сценарий и вариант на каждой стороне. Для сравнения GCC и Clang явно разрешите различие build environments и укажите оба ожидаемых fingerprint. Разница будет отмечена как намеренная. Совпадение Host, workload и единиц проверяется отдельно. `DetectAsync` по-прежнему применяет существующие строгие правила сопоставимости и статистической проверки.

`RegressionGate.Evaluate` проверяет медиану в заданном направлении. Порог задаётся в единицах метрики или в процентах от положительного baseline. Точное равенство порогу проходит. Недостающие или несопоставимые данные дают **Inconclusive**. При включённой статистической политике превышение порога требует подтверждения из `DetectAsync` для той же пары. Для CI можно вернуть 0 при Passed, 1 при Failed и 2 при Inconclusive. Код проверки производительности независим от результата workflow.

Утвердите GCC и системный Clang и их release-конфигурации. Затем выведите план и запустите его с подтверждённым SHA-256.

```sh
dotnet run --file examples/engineering/campaign.cs -- PROJECT performance-001
dotnet run --file examples/engineering/campaign.cs -- PROJECT performance-001 REVIEWED_SHA this kit-00-release kit-01-release
```

Здесь `this` явно выбирает замеры GCC из той же матрицы как baseline. Для отдельного baseline передайте run ID из History. Пример ссылается на проект Developer. Пакет Scripting сохраняет зависимости только от Client и Contracts. Запросы History и gates доступны из пакета Client. [Пример кампании](../../examples/engineering/campaign.cs)
