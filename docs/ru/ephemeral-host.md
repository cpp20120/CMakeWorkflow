# Stage F1 — временный Host через SSH.NET и stdio

`CMakeWorkflowClient.LaunchSshNetAsync` запускает установленный на удалённом
Linux-хосте `CMakeWorkflow host serve --stdio` внутри SSH exec-channel.
Отдельный постоянно работающий Host и Unix-сокет не требуются: readiness
подтверждается обычным JSON-RPC `initialize`. PTY не создаётся, stdout — только
бинарные кадры RPC, диагностика — stderr.

Для подключения используются `SshNetLaunchOptions`: адрес сервера, пользователь,
абсолютный локальный путь к приватному ключу, проверенный SHA-256 отпечаток
ключа сервера и абсолютный каталог удалённого workspace. Бинарник уже должен
быть установлен на сервере; автоматического деплоя пока нет.

**Отличие от persistent режима:** время жизни Host ограничено SSH-сеансом.
При нормальном завершении или потере RPC-канала отменяется выполнение,
закрываются сессии и Host завершается. Незавершённые операции не должны
переживать отключение клиента. Потеря соединения сама по себе не доказывает,
что работа не была запущена или не произвела внешних эффектов; после аварии
нужно проверять удалённые журналы. Жёсткое завершение произвольного зависшего
дочернего процесса одним SSH disconnect не гарантируется.

Существующие команды `remote start/find/status` по-прежнему требуют persistent
Host. Не заменяйте их подключение на временное: `start` возвращает ID и
закрывает клиент, а это немедленно инициировало бы остановку временного Host.
Для CLI временного режима позже понадобится отдельная команда `run --wait`.

Контрактные тесты проверяют бинарный stdio-обмен, handshake и выход Host при
EOF. Проверка настоящего sshd, обрыва сети и очистки remote process tree — F3.
